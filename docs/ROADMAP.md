# План v2 шаблону сайту котеджу

**Мета v2:** новий сайт для котеджу чи садиби — за один вечір, якісний і **не схожий** на інші наші сайти.

Стан на 23.11.2026. Цей файл — для продовження роботи в новій сесії: що зроблено, що лишилось, про що домовились.

---

## Домовленості (обов'язкові для всієї v2)

**Процес**
- Кожен пункт плану — **окремий PR**. Виправлення для живих сайтів клієнтів (напр. SVI) — окремими PR у їхні репозиторії.
- Мова коду, коментарів, документації й повідомлень — **українська**.
- На шаблоні працюють **живі клієнти**: жодних змін бази, що видаляють чи переписують дані.
  Лише додавання (`CREATE TABLE IF NOT EXISTS`, нові необов'язкові колонки).
- Нові поля конфігу — **необов'язкові**: якщо поля немає, сайт виглядає й працює як у v1.
  Оновлення шаблону не повинне змінити вигляд наявного сайту.
- Правила з `CLAUDE.md` (числові поля, конфіг замість коду, секрети в `.env`, безпека, `media_url()`) — не послаблювати.
  Тести мають бути зеленими перед кожним комітом.

**Клієнти**
- З клієнтами — **лише листування** (WhatsApp / Viber), без дзвінків. Анкета — не більше 12 коротких питань простою мовою.
- Тексти, alt і SEO — **шаблонами з анкети** з кількома варіантами формулювань, **без зовнішніх AI API**.
  Унікальні тексти під клієнта власник студії допрацьовує окремо вручну.

**Сервер**
- VPS керується репозиторієм `6vkvybwyht-design/yalott-server`: `new-site`, `new-static-site`, `set-domain`,
  `deploy`, `secure-site`, `security-check` — запускаються **на сервері через `sudo`, по SSH, власником студії**.
- Claude **нічого не запускає на сервері**: лише пише команди й чекліст перевірки.
- Безпека кожного сайту: `sudo secure-site НАЗВА --no-cloudflare` (домени клієнтів не за Cloudflare) і `sudo security-check`.
- Взірець безпеки — `svi-cottages-demo` PR #8 (перенесено в шаблон, PR #3).

**Демо для продажу**
- Посилання з терміном дії (типово **14 днів**), необов'язковий пароль (`DEMO_PASSWORD` у `.env`),
  водяний знак «Демо · Yalott Studio» **вшитий у фото**, код не працює на чужому домені, прихована позначка авторства.
- Домен демо — параметр конфігу `demo.domain`. Поки — тестова адреса сервера `НАЗВА.<IP-з-дефісами>.sslip.io`,
  свій домен студії додамо пізніше (змінити лише цей рядок).

## Лишилось (у такому порядку)

### 1. Перевірка якості перед здачею — `manage.py qa`
Іде **перед темами**, щоб ловити, якщо нова тема зламає вигляд живих сайтів.
- Скріншоти **375 px і 1440 px** усіх сторінок (головна, кожен котедж, адмінка), зведені в один HTML-звіт.
- Еталонні знімки поточних конфігів: тест падає, якщо вигляд наявного сайту змінився без наміру.
- **Lighthouse** (продуктивність, доступність, SEO) з порогами.
- **Биті посилання** й фото, яких немає.
- **Форма бронювання** від початку до кінця на тестовій базі, без справжнього Telegram.
- Грошові поля (правило з PR #2), CSP-порушення в консолі, горизонтальна прокрутка на телефоні.

### 2. Тексти й SEO
- Шаблони «Про нас», описів котеджів, FAQ, правил — з даних анкети, **кілька варіантів формулювань**;
  варіант обирається стабільно від назви сайту, щоб тексти різних клієнтів не повторювались.
- Мета-теги, `canonical`, Open Graph для кожної сторінки.
- schema.org: `LodgingBusiness` для головної, окремі об'єкти для котеджів (ціни, місткість, зручності).
- `sitemap.xml`, `robots.txt` (у демо — як зараз, `Disallow: /`).
- Без зовнішніх AI API.

### 3. Унікальність — теми й варіації
- **4–5 тем** (зараз 3): кольори, шрифти, **розкладка головної**, стиль карток, герой-блок — обираються в конфігу.
- **Автоматичні варіації**, щоб два сайти на одній темі відрізнялись; стабільні між перезапусками (від назви сайту).
- Розбити на 3а (система розкладок + нові теми) і 3б (автоваріації).
- Наявні сайти без нових полів виглядають як у v1 — перевіряє еталон зі скріншотів (пункт 1).

### 4. Фото
- Кидаєш папку з фото клієнта → стискання у WebP, розміри, без EXIF (вже є в `manage.py photos`).
- Нове: **розкладання по котеджах** — за підпапками чи префіксом у назві файлу; що не вдалося — списком
  (без нейромереж автоматично «вітальню Великого котеджу» не розпізнати).
- **alt-тексти** з анкети (назва котеджу + що на фото, з підписів чи назви файлу).
- Вибір фото для банера й обкладинок.

### 5. Деплой однією командою — зроблено (див. «Зроблено»)
Лишилось на потім: `--domain` для демо на домені студії (коли з'явиться `demo.domain` студії), перевірка
Lighthouse/скріншотів після запуску — разом із пунктом 1 (`manage.py qa`).

## Відомі борги й зауваги

- **`from-chat` не прибирає фото шаблону.** У шаблоні лежать фото Forest House (`static/media/…`): банер і галерея
  беруть усе з теки, тож без ручного видалення демо клієнта показало б чужі фото. Зараз — команда `rm` у кроках
  нижче; автоматизувати (як у `new-client`, що пропонує видалити демо-фото).
- `from-chat` для `config/site.yaml` шаблону потребує `--force` і лишає `config/site.yaml.bak` — його не комітити.
- Короткі посилання Google Maps (`maps.app.goo.gl/…`) не розкриваються (без мережі) — координати вручну, у конфігу є підказка.
- Описи котеджів після анкети — заглушки з позначкою `ПЕРЕВІРИТИ`, доки немає пункту 2 «Тексти й SEO».
- Логотип і favicon мають лежати в `media/brand/` — інакше в демо вони закриті разом з іншими фото.
- Заголовки безпеки віддає і сайт, і Caddy (`secure-site`); на живому сервері поєднання не перевірене —
  у чеклісті DEPLOY.md є `curl -sI`, який це покаже.
- Сайт без `SECRET_KEY` у `.env` після оновлення шаблону не стартує (так задумано). Сайти з `new-site` ключ мають;
  перед `deploy` старого сайту: `sudo grep -c '^SECRET_KEY=.\+' /home/yalott/sites/НАЗВА/.env` → `1`.
- SVI: інші поліпшення шаблону (суворий CSP без `'unsafe-inline'`, випадковий пароль замість демо) у SVI не перенесені —
  за потреби окремими PR.

## Як зараз робиться демо

Локально:
1. GitHub: **Use this template** → приватний репозиторій клієнта; `git clone`, `python3 -m venv .venv`, `pip install -r requirements.txt`.
2. `python manage.py anketa` → надіслати клієнту; відповіді зберегти в `chat.txt`.
3. `python manage.py from-chat chat.txt --theme wood --force`; видалити `config/site.yaml.bak`.
4. Прибрати фото шаблону: `rm -rf static/media/objects static/media/hero static/media/gallery static/media/extras static/media/brand`.
5. Фото клієнта → `media/objects/<id>/`, `media/hero/`, `media/gallery/`, `media/extras/`; `python manage.py photos`.
6. У `config/site.yaml`: прибрати `ЗАМІНИТИ`, у розділі `demo` — `enabled: true`, `domain: "НАЗВА.<IP-з-дефісами>.sslip.io"`.
7. `python manage.py validate`; закомітити `config/site.yaml` і `static/media/`; `git push`.

На сервері:
8. `sudo launch-site НАЗВА 6vkvybwyht-design/РЕПОЗИТОРІЙ --demo --dry-run` — перегляд, нічого не змінює.
9. `sudo launch-site НАЗВА 6vkvybwyht-design/РЕПОЗИТОРІЙ --demo` — deploy key (один раз), запуск, перевірки
   й посилання для клієнта. За бажанням пароль демо: `DEMO_PASSWORD` у `.env` і `sudo deploy НАЗВА`.

Після оплати: `demo.enabled: false` у конфігу, `git push`, DNS домену → IP сервера, і
`sudo launch-site НАЗВА 6vkvybwyht-design/РЕПОЗИТОРІЙ --domain ДОМЕН` (домен + `secure-site --no-cloudflare` + перевірки);
потім `seed --clear-demo` (команду покаже launch-site) і `sudo security-check`.
