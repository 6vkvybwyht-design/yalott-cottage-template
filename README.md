# Шаблон сайту котеджу з онлайн-бронюванням

Універсальний шаблон Yalott Studio для котеджів, садиб і шале в Карпатах.
**Новий клієнт = заповнити один файл `config/site.yaml` + покласти фото + задеплоїти.** Код не правиться.

Що вміє сайт:

- сторінка кожного об'єкта, календар зайнятості, автоматичний розрахунок ціни, форма заявки;
- кілька **однакових одиниць** одного об'єкта (напр. «Великий котедж × 2») — бронюються окремо;
- сезонні ціни, доплата за гостей, мінімум ночей, додаткові послуги (чан, баня, сніданки);
- адмінка власника: заявки, календар, ціни, сезони;
- сповіщення власнику в Telegram;
- три теми оформлення: `dark`, `wood`, `forest`.

Стек: Python 3.10+, Flask, SQLite. Без збирання фронтенду — звичайні HTML/CSS/JS.

## Новий клієнт за 30 хвилин

### 1. Створіть репозиторій клієнта

На GitHub: **Use this template → Create a new repository** (приватний, напр. `ramshill-site`). Потім:

```bash
git clone https://github.com/<ваш-акаунт>/ramshill-site.git
```

```bash
cd ramshill-site
```

```bash
python3 -m venv .venv && source .venv/bin/activate
```

```bash
pip install -r requirements.txt
```

### 2. Заповніть конфіг

Найшвидше — майстер у терміналі. Він питає назву, контакти, об'єкти, ціни й створює `config/site.yaml`,
а заодно пропонує видалити демо-фото шаблону:

```bash
python manage.py new-client
```

Далі відкрийте `config/site.yaml` і допишіть те, чого майстер не питає: описи, зручності, FAQ, відгуки,
«що поруч». Кожне поле підписане українською. Готові зразки — `config/examples/ramshill.yaml`
і `config/examples/blackhouse.yaml`.

Перевірте конфіг — помилки пояснюються людською мовою (якого поля бракує, де неправильна дата,
які сезони перетинаються, де немає фото):

```bash
python manage.py validate
```

### 3. Покладіть фото

Оригінали «як є» (з телефона чи фотоапарата) — у папку `media/`:

```
media/
  objects/<id об'єкта>/   фото об'єкта: 01.jpg, 02.jpg… (перше — обкладинка)
  hero/                   одне фото для банера головної
  gallery/                територія, краєвиди
  extras/                 фото послуг, ім'я = id послуги: chan.jpg
  brand/                  logo.png, logo-light.png, favicon.png (необов'язково)
```

Обробіть їх — скрипт виправляє орієнтацію (EXIF), стискає у WebP, робить розмір для десктопа (1600 px)
і для мобільного (600 px), прибирає метадані (GPS, модель телефона):

```bash
python manage.py photos
```

Готові фото з'являться у `static/media/` — саме вони йдуть у git і на сервер.
Якщо фото ще немає, сайт показує акуратну заглушку в кольорах теми, а не зламаний блок.

### 4. Секрети

```bash
cp .env.example .env
```

Заповніть у `.env`: `SECRET_KEY`, `ADMIN_PASSWORD`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
Секрети зберігаються **тільки** в `.env` (він не потрапляє в git). У конфігу їх бути не може —
`validate` на це свариться.

### 5. Запустіть і подивіться

```bash
python manage.py seed
```

```bash
python app.py
```

Сайт: <http://localhost:5000>, адмінка: <http://localhost:5000/admin>.
З `DEMO_DATA=1` у `.env` нова база одразу заповнюється демо-зайнятістю й двома демо-заявками —
зручно показувати клієнту. Перед запуском для гостей приберіть їх: `python manage.py seed --clear-demo`.

### 6. Перевірте готовність і задеплойте

```bash
python manage.py check
```

Команда перевіряє конфіг, `.env`, фото й базу та каже, чого бракує. Коли все зелене —
комітьте `config/site.yaml` і `static/media/` та йдіть у **[DEPLOY.md](DEPLOY.md)**.

## Команди

| Команда | Що робить |
|---|---|
| `python manage.py new-client` | майстер: питає українською назву, контакти, об'єкти, ціни → `config/site.yaml` |
| `python manage.py validate` | перевіряє конфіг, пише зрозумілі помилки |
| `python manage.py seed` | заливає конфіг у базу; повторний запуск безпечний |
| `python manage.py seed --reset` | свідомо перезаписує ціни й сезони значеннями з конфігу |
| `python manage.py seed --demo` / `--clear-demo` | додає / прибирає демо-дані |
| `python manage.py photos` | обробляє фото з `media/` у `static/media/` (`--force` — усі заново) |
| `python manage.py check` | чи все готово до деплою |
| `python manage.py set-password` | змінює пароль адмінки |

До будь-якої команди можна додати `--config шлях/до/файлу.yaml`.

## Приклади

Обидва запускаються без правок коду:

```bash
SITE_CONFIG=config/examples/ramshill.yaml DEMO_DATA=1 python app.py
```

```bash
SITE_CONFIG=config/examples/blackhouse.yaml DEMO_DATA=1 python app.py
```

- **ramshill.yaml** — тема `wood`; «Великий котедж» × 2 і «Маленький котедж» × 4, чан за вечір.
- **blackhouse.yaml** — тема `dark`; різний час заїзду в котеджів, чан-джакузі з ціною за кількістю гостей,
  передоплата 50%.
- **config/site.yaml** — демо «Forest House», тема `forest`, з фото.

У кожного конфігу своя база (`instance/<назва>.db`) і свої фото
(`site.yaml` → `media/`, інші → `media/examples/<назва>/`), тож приклади не заважають один одному.

## Як влаштовані дані: конфіг чи адмінка

| Що | Де живе | Як змінити |
|---|---|---|
| Назва, контакти, тексти, фото, тема, блоки, FAQ, відгуки | `config/site.yaml` | правка файлу + перезапуск сайту |
| Передоплата, час заїзду/виїзду, правила скасування | `config/site.yaml` | так само |
| Ціна за ніч, доплата за гостя, гості, одиниці, мінімум ночей | **база** (початково з конфігу) | адмінка → «Ціни» |
| Сезони, ціни послуг | **база** (початково з конфігу) | адмінка → «Ціни» |
| Бронювання, закриті ночі | база | адмінка |

**Конфіг — це початкові дані.** Під час першого запуску (і командою `seed`) поля з позначкою `[БАЗА]`
записуються в базу. Далі власник змінює їх в адмінці, і ці правки мають пріоритет:

- `seed` додає лише те, чого в базі ще немає (новий об'єкт, послугу, сезон);
- ціну, яку власник змінив, `seed` не чіпає — лише показує різницю з конфігом;
- сезон, який власник видалив, `seed` не повертає;
- бронювання й закриті ночі не змінюються ніколи.

Якщо треба свідомо скинути ціни й сезони до конфігу: `python manage.py seed --reset`.

## Як рахується ціна

```
разом = Σ по ночах (ціна сезону, якщо ніч у сезоні, інакше базова)
      + ночі × гості понад базу × доплата за гостя
      + додаткові послуги
```

- Бронь може перетинати межу сезону — кожна ніч рахується за своєю ціною.
- Сезон конкретного об'єкта має пріоритет над сезоном «для всіх».
- Сезон «за домовленістю» (`on_request: true`): сайт не рахує суму, заявку приймає.
- Послуга: `evening`/`once` — один раз, `night` — × ночі, `person` — × гості, `person_night` — × гості × ночі;
  ціна може залежати від кількості гостей (`guest_prices`).
- Необов'язкова знижка за тривалість (`long_stay`).

Сервер завжди перераховує суму сам (`pricing.py`); у браузері — копія формули (`static/js/pricing.js`).

**Кілька одиниць.** Об'єкт із `units: 2` — це два однакові котеджі. Ніч закрита для бронювання,
лише коли зайняті всі одиниці. Перевірка й запис ідуть в одній транзакції, тому дві одночасні
заявки на останню одиницю не пройдуть обидві.

## Теми

`brand.theme` у конфігу: `dark` (чорно-графітова, теплі вогні), `wood` (світла, дерево),
`forest` (темно-зелена). Кольори — CSS-змінні на початку `static/css/style.css`.
Свій основний і акцентний колір: `brand.primary_color` і `brand.accent_color` — відтінки перерахуються самі.

## Структура проєкту

```
config/site.yaml         конфіг клієнта (єдиний файл, який редагується)
config/examples/         готові приклади
site_config.py           читання й перевірка конфігу
pricing.py               формула ціни (чисті функції)

notifications.py         Telegram
gallery.py, photos.py    фото: показ і обробка
manage.py                команди
templates/, static/      шаблони, стилі, скрипти, готові фото
media/                   оригінали фото (не в git)
tests/                   тести
```

## Що закладено під v2

Не реалізовано, але архітектура готова:

- **iCal (Booking / Airbnb).** У `blocked_nights` і `bookings` є поле `source`; закриті ночі зберігаються
  окремо для кожного джерела. Імпорт календаря писатиме рядки `source = 'ical:<назва>'` і оновлюватиме
  лише їх, не чіпаючи закриття власника. Експорт — це вибірка активних бронювань.
- **Онлайн-оплата (LiqPay / WayForPay / mono).** У `bookings` є `prepayment`, `payment_status`, `payment_ref`.
  Провайдер підключається окремим модулем; секрети — у `.env`.
- **Telegram-бот з кнопками «Підтвердити / Скасувати».** Статус змінюється в одній функції
  `database.set_status()` — нею вже користується адмінка, бот викликатиме її ж.
- У конфігу зарезервовано розділ `integrations:` — зараз сайт його лише зчитує.
