# CLAUDE.md — шаблон сайту котеджу (Yalott Studio)

Інструкції для Claude та розробників, які змінюють цей шаблон. Відповідати й писати тексти — українською.

## ОБОВ'ЯЗКОВІ ПРАВИЛА

### 1. Числові поля й гроші — тільки `step="1"`, гроші — `min="0"`

- **Грошове поле** (ціна, доплата, ціна послуги, сума — усе в гривнях):
  ```html
  <input type="number" inputmode="numeric" min="0" step="1" data-money …>
  ```
  У `static/js/admin.js` — лише через `moneyInput()` / `moneyField()`.
- **Будь-яке інше числове поле** (гості, ночі, одиниці): `step="1"`, або `step="any"`, якщо справді потрібні дроби.
- **Ніколи:** `step="50"`, `step="100"`, `step="500"`, `min="1"` у грошовому полі, `step` без значення,
  `step`, виставлений зі скрипта (`el.step = …`, `setAttribute('step', …)`), чи значення, склеєне зі змінної.
  `step` і `min` пишуться в розмітці буквально.

**Чому.** Браузер рахує крок від `min`: з `min="1" step="50"` валідні лише 1, 51, 101 … 4451, 4501, тож
форма мовчки не зберігає ціну **4500**. Через це вже двічі ламалось у клієнтів.

Нижню межу ціни (наприклад, «ціна за ніч > 0») перевіряє **сервер** (`admin.py`, `_price`) і пояснює
помилку власнику. Браузерне `min` для грошей завжди `0`.

**Перевірка:** `tests/test_number_inputs.py` проходить усі шаблони (`templates/**/*.html`), скрипти
(`static/**/*.js`), готові сторінки всіх конфігів і живий DOM адмінки в браузері (кожне грошове поле
має прийняти 4500 і 20000). Тест має бути зеленим перед кожним комітом. Не послаблюйте й не пропускайте
його — виправляйте поле.

### 2. Клієнт = конфіг, а не код

Усе про конкретного клієнта — у `config/site.yaml`. Назви, ціни, контакти, тексти в шаблони й код
не вписуються. Нове налаштування — нове поле конфігу з коментарем українською й перевіркою в
`site_config.validate()`.

### 3. Секрети — тільки в `.env`

Паролі, токени, chat id — лише в `.env` (не в git). У конфігу їх бути не може: `validate` на це свариться.

### 4. Правки власника не перезаписуються

Ціни, сезони й параметри об'єктів після першого `seed` живуть у базі. `seed` має лишатися безпечним
для повторного запуску: додає лише нове, змінене в адмінці не чіпає.

### 5. Безпека з коробки — не послаблювати

Захист вмикається сам для кожного сайту (`security.py`, `admin.py`, `app.py`); перевірка — `tests/test_security.py`.

- **Жодних вбудованих `<script>`, `onclick=`/`on…=`, `javascript:`, `<style>` і `style=""`** — ні в шаблонах,
  ні в HTML, який будує JS. Сайт працює під суворим Content-Security-Policy без `'unsafe-inline'`.
  Скрипт — окремим файлом у `static/js/`, стиль — у `static/css/` (свої кольори теми — `/theme.css`).
  Дозволено лише `<script type="application/ld+json">` (дані schema.org).
- Новий зовнішній сервіс (аналітика, віджет, відео) — дописати його адресу в `security.content_security_policy()`.
- Кожна форма й кожен POST — з CSRF-токеном (`security.token_ok`, ніколи `==`).
- IP відвідувача — лише `request.remote_addr` / `app.client_ip()` (за ProxyFix), **ніколи** напряму `X-Forwarded-For`.
- Ліміти (вхід, заявки) — у базі через `security.py`, не в пам'яті процесу й не через `sleep`.
- `SECRET_KEY` — лише з `.env`, без запасних значень. Секрети з `.env` не логуються й не потрапляють у шаблони.
  Єдиний виняток — одноразовий випадковий пароль першого адміністратора, якщо `ADMIN_PASSWORD` не задано:
  він пишеться в журнал сайту (доступ — лише `sudo`), бо інакше власник не зможе увійти.
- Текст із форм — через `security.clean_text`; типи полів перевіряються на сервері.
- Зовнішні адреси (iCal тощо) — лише через `security.fetch_public` (https, без внутрішніх адрес).
- Зміни бази — лише додавання (`CREATE TABLE IF NOT EXISTS`, нові необов'язкові колонки). Нічого, що видаляє
  чи переписує дані: на шаблоні працюють живі клієнти.

## Команди

```bash
python -m pytest                 # усі тести
python manage.py anketa          # опитувальник для клієнта (WhatsApp / Viber)
python manage.py from-chat chat.txt   # відповіді з чату → config/site.yaml + дозапит
python manage.py validate        # перевірити конфіг
python manage.py check           # готовність до деплою
SITE_CONFIG=config/examples/ramshill.yaml DEMO_DATA=1 python app.py   # приклад
```

Змінили питання в `chat_import.QUESTIONS` — оновіть копію: `python manage.py anketa > docs/anketa-dlya-klienta.txt`
(тест перевіряє, що вони однакові). Нове поле конфігу з анкети — додайте його розбір у `chat_import.parse_chat`
і фікстуру чату в `tests/fixtures/chats/`.

Докладно — `README.md`, деплой — `DEPLOY.md`.
